[Markdown を PDF にする](/)ツールは、サーバーを使わず、ブラウザの中だけで「Markdown の変換 → プレビュー → PDF の保存」を行います。この記事では、ボタンの裏側で実際に何をしているのかを、処理の順に説明します。どこまで任せてよいか、どんなときに思いどおりにならないかを判断する材料にしてください。

書き方そのものは[Markdown の書き方早見表](/guide/markdown-syntax/)、用紙や余白の選び方は[見やすい PDF を作るコツ](/guide/pdf-tips/)にまとめています。

## 全体の流れ

1. 入力した Markdown のテキストと、一緒に入れた画像を、ブラウザのメモリに置きます。
2. Markdown を HTML に変換します。このとき、安全でない書き方は文字として残し、外部の画像は読み込まない形にします。
3. 変換した HTML と、用紙・余白・文字サイズの設定から作った CSS を 1 つの HTML 文書にまとめ、プレビューの枠（iframe）に表示します。
4. 「PDF を保存」を押すと、そのプレビューの枠の中身だけをブラウザの印刷機能に渡します。印刷の画面で「PDF に保存」を選ぶと PDF になります。

画面に見えているプレビューが、そのまま印刷される文書です。プレビュー用と印刷用で別々に作り直しているわけではないので、プレビューで確認した内容と PDF の内容は同じになります（ページの区切り方だけは、次に説明するとおりブラウザが印刷時に決めます）。

## Markdown を HTML にする部分

変換には、広く使われているオープンソースのライブラリ **markdown-it** を使っています。表や取り消し線といった GitHub でおなじみの記法に加え、2 つの拡張を入れています。

- **脚注**（`[^1]` と書いて、文末に注を並べる記法）
- **タスクリスト**（`- [ ]`・`- [x]` のチェックボックス。PDF 用なので、クリックしても切り替わらない表示だけのものです）

また、文中に `https://` で始まる URL をそのまま書くと、自動でリンクになるよう設定しています。

このライブラリは、最初に画面を開いたときには読み込まず、変換が必要になった瞬間に読み込みます。ページを開いてすぐ使い始められるようにするためです。

### 生の HTML は解釈しない

Markdown の仕様では、本文に HTML のタグを直接書けます。しかしこのツールは、その機能を**オフ**にしています（markdown-it の `html: false`）。タグを書いても、タグの形のまま文字として表示されます。

理由は安全のためです。人からもらった Markdown や、どこかからコピーした文章に、スクリプトや外部のページを読み込むタグが紛れ込んでいても、それが動いたり通信したりすることはありません。その代わり、文字の色や中央寄せのように HTML に頼る装飾は使えません。

### リンクにする URL を選ぶ

リンクや画像に書かれた URL は、使ってよい種類かどうかを確かめてから HTML にしています。リンクとして受け付けるのは次のものだけです。

- `http:`・`https:`・`mailto:`（メール）・`tel:`（電話）
- 相対パスや `#見出し` のようなページ内の移動
- 画像を直接埋め込んだ `data:image/...`（PNG・JPEG・GIF・WebP・AVIF・SVG）

`javascript:` などそれ以外の種類は、リンクにせず文字のまま残します。ブラウザは URL の途中のタブや改行、前後の空白を無視して読むため、判定もその形にそろえてから行い、`java` と `script:` の間に改行を挟むような書き方ですり抜けないようにしています。

## プレビュー：外とつながらない枠の中に表示する

変換した HTML は、ページ本体とは切り離した iframe（ページの中の別の小さなページ）に表示します。この枠には 2 重の制限をかけています。

### スクリプトが動かない枠

iframe には `sandbox` という、中でできることを絞る仕組みがあります。このツールでは、スクリプトの実行を許す設定（`allow-scripts`）を**付けていません**。万一、変換結果に何か紛れ込んでも、枠の中でプログラムが動くことはありません。印刷やスクロール位置の保持、リンクのクリックは、枠の外のページ本体が受け持っています。

そのため、プレビューのリンクの動きも少し特殊です。`#` で始まるページ内のリンクは枠の中でその見出しまでスクロールし、外部のリンクはページ本体が新しいタブで開きます（開くのは `http:`・`https:`・`mailto:`・`tel:` だけです）。

### 外部と一切通信しない文書

プレビューの文書の先頭には、読み込んでよいものを決める CSP（コンテンツ セキュリティ ポリシー）を入れています。中身は次のとおりで、ページ本体の CSP よりも厳しくしています。

- 原則として何も読み込まない（`default-src 'none'`）
- 画像は `data:` と `blob:`（＝手元で一緒に入れた画像）だけ
- 見た目は文書の中に書いた CSS だけ

つまり、文書の中から外部のサーバーへ画像を取りに行ったり、Web フォントを読み込んだりすることは、ブラウザの仕組みとして止められています。リンク元を伝える情報（リファラー）も送らない設定です。

## 画像の扱い

外部 URL の画像（`https://...` の画像）は読み込みません。読み込むと、その画像のサーバーに「誰かがこの文書を開いた」ことが伝わってしまうためです。代わりに「画像を表示できません」という枠を出します。

画像を表示するには、「画像を追加」で画像ファイルを入れます。本文の `![説明](images/photo.png)` のような相対パスと、入れたファイルを次の順で照らし合わせます。

1. フォルダを含めた相対パスが一致するもの（`./` や `../`、`?` 以降は整えてから比べます）
2. ファイル名が一致するもの
3. 大文字と小文字を区別せずにファイル名が一致するもの

入れた画像は、端末の外に出さずに表示用の URL に変えます。ここにも安全のための工夫があります。

- **SVG** は、`data:image/svg+xml;base64,...` の形にします。SVG は中にスクリプトを含められる形式なので、サイトと同じ権限を持つ URL にせず、種類を固定した data: URL として画像としてだけ表示します。
- **それ以外**（PNG・JPEG・GIF・WebP・AVIF）は、ファイルの拡張子から決めた種類（MIME）を付け直して、`blob:` の URL にします。ファイルが自称する種類はそのまま信用しません。
- 受け付けない拡張子のファイルには、表示用の URL を作りません。

画像は印刷時にページの途中で切れないよう、また用紙の幅を超えないように縮めて配置します。

## PDF はブラウザの印刷機能で作る

このツールは PDF を作るライブラリを使わず、ブラウザ自身の印刷機能で PDF にしています。「PDF を保存」はプレビューの枠の中身だけを印刷に回すボタンで、印刷している間だけ文書のタイトル（本文の最初の `#` 見出し）を保存名の初期値にしています。

### この方法の利点

- **文字が文字のまま残る**：PDF の中の文字を選んでコピーしたり、検索したりできます。画像として貼り付けた PDF とは違います。
- **端末の日本語フォントがそのまま使える**：書体は、ヒラギノ・游ゴシック・メイリオ・Noto などの、端末に入っているフォントから選ばれます（明朝を選んだときも同様）。フォントをネットから取ってこないので、通信が発生しません。
- **リンクが生きる**：多くのブラウザでは、PDF の中のリンクもクリックできます。
- **組版を CSS で細かく決められる**：見出しの直後でページが変わらない、表の 1 行やコードのまとまり・画像がページの境目で分かれにくい、表の見出し行を次のページでも繰り返す、といった指定を入れています。

### この方法の限界

- **ブラウザや OS で仕上がりが少し変わる**：使われるフォントは端末によって違うため、同じ Markdown でも、Windows と Mac では文字の形や 1 行に入る文字数、改ページの位置がずれることがあります。人に渡す PDF は、作った PDF を開いて確認してください。
- **ヘッダーとフッターはブラウザの設定**：日付・タイトル・URL・ページ番号が上下に入るのは、ブラウザの印刷設定の「ヘッダーとフッター」が原因です。ツールからは消せないので、印刷の画面でオフにしてください。逆に言えば、ページ番号が欲しいときはオンのままにする方法もあります。
- **ページの区切りはブラウザが決める**：「なるべく分けない」指定はしていますが、1 ページに入りきらない長い表やコードは、途中で分かれます。

## ページ設定の中身

設定は印刷用の CSS に変換されます。選べる値は次のとおりです。

| 項目 | 選べる値 | 既定 |
| --- | --- | --- |
| 用紙 | A4（210×297mm）・Letter（215.9×279.4mm） | A4 |
| 向き | 縦・横 | 縦 |
| 余白（上下左右） | 狭い 10mm・標準 20mm・広い 30mm | 標準 |
| 文字サイズ | 9・10・11・12・14pt | 11pt |
| 書体 | ゴシック・明朝 | ゴシック |
| `---` で改ページ | オン・オフ | オン |

「`---` で改ページ」がオンのとき、水平線の位置で次のページに移ります。プレビューでは、そこに点線を引いて区切りを示します。脚注の上に入る区切り線では改ページしません。

PDF は、画面がダークモードでも、常に白地に黒い文字で作ります。背景の色（コードや表の見出しの網掛け）が消えないよう、印刷でも背景色を出す指定も入れています。

## 入力の上限

ブラウザが重くなって固まるのを防ぐため、次の上限を設けています。

- Markdown のテキスト：2MB まで（UTF-8 のバイト数。日本語ならおよそ 70 万文字）
- 読み込める文書ファイル：`.md`・`.markdown`・`.txt`（1 度に 1 つ）
- 一緒に入れる画像：50 枚まで、合計 20MB まで。同じ名前の画像を入れ直すと置き換わります

## 入力した内容の行方

文書と画像は、運営者のサーバーに送信しません。変換も印刷も、すべてお使いのブラウザの中で行います。

再読み込みで消えないよう、編集中のテキストとページ設定だけは、ブラウザの sessionStorage（そのタブの中だけの一時的な保存場所）に置いています。タブを閉じると消え、ほかのタブや運営者からは見えません。画像は保存せず、再読み込みすると入れ直しが必要です。

## まとめ

- Markdown の変換は markdown-it。生の HTML は文字として表示し、安全でない URL はリンクにしない
- プレビューはスクリプトが動かず、外部と通信できない枠の中。そのプレビューがそのまま PDF になる
- 外部の画像は読み込まず、手元で入れた画像だけを種類を固定した URL で表示する
- PDF はブラウザの印刷機能で作るので、文字を選べる一方、フォントや改ページは端末によって少し変わる

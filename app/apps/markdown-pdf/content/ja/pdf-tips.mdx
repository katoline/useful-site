Markdown で書いた文書は、そのままでも読めますが、人に渡したり印刷したりするなら PDF にしておくと、どの端末でも同じ見た目で開けます。[Markdown を PDF にする](/)ツールを使えば、Markdown を用紙に合わせて整え、ブラウザの印刷機能で PDF として保存できます。

ただ、画面で読みやすい文書と、紙や PDF で読みやすい文書は少し違います。この記事では、用紙の選び方から改ページ、表や画像の扱い、保存の手順まで、見やすい PDF にするための実践的なコツをまとめます。Markdown の記法そのものは[Markdown の書き方早見表](/guide/markdown-syntax/)を参照してください。

## 用紙と向きを決める

最初に、PDF を読む人が使う用紙に合わせます。ツールの「ページ設定」では、用紙を A4 と Letter から選べます。

- **A4（210×297mm）**：日本やヨーロッパなど、多くの国で標準の大きさです。国内で使う文書は、基本的に A4 を選びます。
- **Letter（215.9×279.4mm）**：アメリカやカナダで標準の大きさです。A4 より少し幅が広く、高さが低い紙です。北米の取引先に送る文書や、向こうで印刷されることが分かっている文書に使います。

用紙が違うと、受け取った側で印刷したときに縮小されたり、端が切れたりすることがあります。迷ったら、読む人のいる地域の標準に合わせるのが安全です。

向きは、文章が中心なら「縦」にします。列の多い表や横長の図が主役の文書は「横」が向いています。なお、向きは文書全体に対する設定で、ページごとに縦と横を混ぜることはできません。横向きが必要な表が一部だけなら、その表だけを別の文書にして PDF にする方法もあります。

## 余白を選ぶ

余白は「狭い（10mm）」「標準（20mm）」「広い（30mm）」の 3 段階で、上下左右に同じ幅が付きます。

- **標準（20mm）**：たいていの文書はこれで十分です。1 行の長さがほどよく、読みやすくなります。
- **狭い（10mm）**：表を少しでも広く使いたいときや、ページ数を減らしたいときに。ただし 1 行が長くなると、行の終わりから次の行の頭へ目を移しにくくなります。文章が多い文書には向きません。
- **広い（30mm）**：印刷してパンチで穴を開ける、ファイルに綴じる、余白に手書きでメモを入れてもらう、といった使い方に向いています。

## 文字サイズと書体を決める

文字サイズは 9・10・11・12・14pt から選べます（初期値は 11pt）。

紙に印刷して読む文書なら、10〜11pt が目安です。日本語の事務文書でよく使われる 10.5pt に近い大きさで、A4 縦・標準の余白なら 1 行に 40 字あまりが入ります。注記の多い資料や、情報を 1 枚にまとめたい一覧表は 9pt にすると収まりがよくなりますが、それより小さい字を長く読むのはつらいので、本文全体を 9pt にするのは避けたほうが無難です。

スマートフォンで PDF を開いて読む人が多いと分かっているなら、12pt にすると拡大せずに読みやすくなります。高齢の方に配る案内や、掲示用の文書は 14pt も検討してください。

書体は「ゴシック」と「明朝」を選べます。ゴシックは線の太さが均一で、画面でも小さい字でもくっきり見えます。明朝は長い文章を紙で読むときに目が疲れにくいとされ、報告書や読み物らしい落ち着いた印象になります。迷ったら、画面で読まれるものはゴシック、印刷して読まれる長文は明朝、と考えるとよいでしょう。

書体は、お使いの端末に入っている日本語の書体を使います（Mac ならヒラギノ、Windows なら游ゴシック・游明朝など）。PDF には使った書体が埋め込まれるので、受け取った人の環境で見た目が変わる心配はほとんどありません。

## 見出しで文書の骨組みを作る

PDF は、ページをめくりながら目で探して読まれることが多い形式です。見出しを整えるだけで、ぐっと読みやすくなります。

- `#`（h1）は文書のタイトルとして最初に 1 回だけ使います。このツールでは、最初の h1 が PDF の保存名の初期値になるので、ファイル名にしたい題名を書いておくと保存の手間が減ります。
- 章は `##`、節は `###` のように、レベルを飛ばさずに使います。`##` の下にいきなり `####` を置くと、文字の大きさの差が開きすぎて構造が分かりにくくなります。
- 見出しは短く、中身を表す言葉にします。「その他」「補足」が並ぶより、「申込みの締め切り」「費用の内訳」のほうが探しやすくなります。
- 1 つの章が長くなったら、`###` で区切って小見出しを付けます。目安は、1 ページに 1〜2 個の見出しが見えるくらいです。

このツールでは、見出しがページの最後の行に取り残されて本文だけが次のページに送られる、という事態をなるべく避けるようにしています。見出しの直後で改ページしないように指定しているためです。

## 改ページを思いどおりにする

ページの切れ目は、ブラウザが自動で決めます。そのうえで、ツールは次のような部分をなるべくページの途中で分けないように指定しています。

- 見出しの直後
- 表の 1 行（行の途中でページが分かれない）
- コードブロック・引用・画像

ただし、1 ページに収まらないほど長いコードブロックや引用は、どうしても途中で分かれます。

章の区切りで必ず新しいページから始めたいときは、「--- で改ページする」をオンにして（初期設定でオンです）、区切りたい位置に `---` の行を書きます。プレビューには改ページの位置が点線で表示されるので、保存する前に確認できます。

```markdown
## 1. 概要

概要の本文……

---

## 2. 詳細

詳細の本文……
```

改ページを入れるときのコツは次のとおりです。

- `---` の前には必ず空行を入れます。文の行のすぐ下に `---` を書くと、その行が見出しになってしまいます。
- 表紙を作りたいときは、タイトルと日付・作成者だけを書いて `---` で区切ると、1 ページ目が表紙になります。
- 最後に `---` を書くと、末尾に白紙のページができることがあります。文書の最後には置かないようにします。
- ブログ用の Markdown ファイルにある、先頭の `---` で囲んだフロントマターは消しておきます。残っていると、1 ページ目が白紙になる原因になります。

改ページではなく区切りの線を引きたいだけのときは、「--- で改ページする」をオフにします。

脚注は、ページごとではなく文書の最後にまとめて出ます。脚注の前の区切り線では改ページしません。

## 表を読みやすくする

表は、PDF で読みにくくなりやすい要素です。このツールでは、表が紙からはみ出さないよう、列の幅を縮めて文字を折り返します。列が多すぎると 1 つのセルに 1〜2 文字しか入らず、単語の途中で折り返されてしまいます。

- **列を減らす**：A4 縦・標準の余白・11pt なら、4〜5 列までが読みやすさの目安です。それ以上必要なら、表を 2 つに分けるか、重要でない列を外します。
- **横向きにする**：列を減らせない一覧表は、「向き」を「横」にすると幅に余裕ができます。文字サイズを 9〜10pt に下げる、余白を「狭い」にする、を組み合わせるとさらに広く使えます。
- **セルの中身を短くする**：セルの中では改行できません。説明文は表の外に箇条書きで書き、表には短い言葉や数値だけを入れます。
- **数値は右寄せにする**：区切り行で `---:` と書くと右寄せになり、金額や件数の桁がそろって比べやすくなります。

複数のページにまたがる長い表では、多くのブラウザで見出しの行が各ページの先頭に繰り返し表示されます。行の途中でページが分かれることもないので、長い一覧表も安心して入れられます。

## 画像のサイズと解像度

画像は「画像を追加」で入れたファイルが使われます（外部 URL の画像は読み込みません）。PDF での大きさは次のように決まります。

- 画像は、本文の幅に収まるように縮小されます。拡大はされません。
- 画面の 96 ピクセルがおよそ 1 インチ（25.4mm）として扱われるので、たとえば幅 400 ピクセルの画像は、幅約 10.6cm で表示されます。
- A4 縦・標準の余白の本文の幅は 170mm です。画像を本文の幅いっぱいに見せたいなら、幅が 650 ピクセル程度は必要です。

印刷してもぼやけないようにするには、表示する大きさの 2 倍程度のピクセル数がある画像を使い、本文の幅に合わせて縮小させるのがおすすめです。本文の幅いっぱいなら、幅 1,300〜2,000 ピクセルほどあれば十分きれいに印刷できます。逆に、画像を小さく見せたいときは、画像ファイルそのものを小さくしておく必要があります（Markdown では表示する大きさを指定できないためです）。

図やグラフは、拡大してもぼやけない SVG で書き出せるなら SVG がいちばんです。写真は JPEG、文字の入ったスクリーンショットは PNG が向いています。画像が大きすぎると PDF のファイルも重くなるので、メールで送るなら、必要以上に大きな写真は縮小してから入れましょう。

## ヘッダーとフッターを消す

ブラウザの印刷機能には、ページの上下に日付・ページのタイトル・URL・ページ番号を入れる「ヘッダーとフッター」の設定があります。オンのまま保存すると、文書と関係のない URL などが PDF に入ってしまうので、オフにしてから保存します。

この設定をオフにすると、ページ番号も入らなくなります。ブラウザのヘッダーとフッターは、日付や URL と一緒にまとめてオン・オフする仕組みのため、ページ番号だけを残すことはできません。ページ番号が必要な場合は、各章の見出しに番号を振っておくと、ページ番号が無くても参照しやすくなります。

## ブラウザごとの保存の手順

ツールの「PDF を保存」を押すと、ブラウザの印刷の画面が開きます。そこから PDF として保存します。

- **Chrome・Edge（パソコン）**：送信先を「PDF に保存」にし、「詳細設定」を開いて「ヘッダーとフッター」のチェックを外します。「余白」は「デフォルト」のままにすると、ツールで選んだ余白が使われます。「倍率」も既定のままにしておきます。
- **Safari（Mac）**：印刷の画面で「ヘッダとフッタをプリント」をオフにし、左下の「PDF」から「PDF として保存」を選びます。
- **iPhone・iPad**：プリントの画面で共有ボタンを押し、「ファイルに保存」を選びます。保存した PDF は「ファイル」アプリで開けます。
- **Android（Chrome）**：プリンタを「PDF 形式で保存」にして、PDF のボタンを押します。

印刷の画面に用紙サイズの選択が出ている場合は、ツールの「ページ設定」と同じ用紙になっているかを確かめてください。ブラウザによっては、印刷の画面の設定が優先されることがあります。

表の見出しの行やコードの背景の薄い色は、PDF にもそのまま入るよう指定しています。もし色が抜けてしまう場合は、印刷の画面の「背景のグラフィック」をオンにしてください。

保存した PDF は、最後にもう一度開いて、改ページの位置、表の折り返し、画像の大きさ、余計なヘッダーが入っていないかを確認しておくと安心です。

## 文書は端末の外に送られない

このツールは、Markdown の変換も PDF の保存も、すべてお使いのブラウザの中で行います。書いた文書や入れた画像を、サーバーに送ることはありません。プレビューの中では外部との通信を禁止していて、外部 URL の画像を読み込まないのもそのためです。

入力中の文書とページ設定は、再読み込みで消えないよう、そのタブの中だけに一時的に保存します。タブを閉じると消えるので、後で書き直す可能性がある文書は「.md を保存」で Markdown のファイルとして手元に残しておきましょう。詳しくは[プライバシーポリシー](/privacy/)をご覧ください。

## 使いどころの例

- **議事録**：決定事項はタスクリスト、担当と期限は表にすると、会議の後にそのまま配れる形になります。日付と会議名を h1 にしておけば、保存名もそのまま使えます。
- **手順書・マニュアル**：手順は番号付きリスト、入力するコマンドや設定値はコードブロックにします。章ごとに `---` で改ページすると、必要な章だけ印刷しやすくなります。
- **報告書**：表紙をつけ、章を `##`、節を `###` で組み立てます。出典や補足は脚注にすると、本文の流れを止めずに書けます。長い報告書は明朝体にすると落ち着いた印象になります。
- **職務経歴書などの書類**：経歴を表や箇条書きで整理して、A4・明朝体・標準の余白で出力します。決まった様式の履歴書のように、枠の位置が指定されている書類には向きませんが、自由な形式の書類なら十分に整った見た目にできます。
- **README や技術文書**：開発の文書を、Markdown を読まない人にも渡せる形にできます。ただし、README によくある HTML のタグ（中央寄せの指定や画像のタグ）と、外部 URL のバッジ画像は表示されません。HTML は Markdown の記法に書き換え、必要な画像は端末に保存してから「画像を追加」で入れてください。

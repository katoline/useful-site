画像の変換・圧縮ツールは、見た目が似ていても、中で使っているエンコーダーや設定の解釈がツールごとに違います。同じ「品質 80」でも、ツールが違えばファイルサイズも画質も変わりますし、EXIF や色プロファイルの扱いも異なります。

この記事では、[変換・圧縮ツール](/)が画像を受け取ってから保存できる形にするまでに、実際に何をしているかを順に説明します。結果が思ったとおりにならないときや、設定の意味を詳しく知りたいときの参考にしてください。形式そのものの違いは[画像形式の選び方](/guide/image-formats/)で、Web サイト向けの使い方は [LP の画像を軽くするコツ](/guide/optimize-lp-images/)で解説しています。

## 処理の流れ

1 枚の画像は、次の順で処理します。

1. **形式の判定**：ファイル名の拡張子ではなく、ファイルの先頭のバイト列（マジックナンバー）で PNG・JPEG・WebP・GIF を見分けます。拡張子を書き換えただけの画像でも、中身の形式で扱います。SVG はテキストなので、中身で判定できないときに限り、拡張子か MIME タイプが SVG のものを SVG として扱います。
2. **大きさの確認**：ファイルの見出し部分から幅と高さを読み、端末の上限（後述）を超える画像はデコードする前に止めます。
3. **デコード**：PNG・JPEG・WebP は、いったん RGBA のピクセルの並びに展開します。
4. **リサイズ**：指定があれば、Lanczos3 という方式で縮小・拡大します。
5. **エンコード**：選んだ形式に書き出します。目標サイズを指定したときは、ここで品質を何度か変えて書き出し直します。
6. **仕上げ**：色プロファイル（ICC）を埋め込み直し、元より大きくなっていないかを確かめます。

GIF と SVG はピクセルに展開せず、それぞれ専用の最適化ツールで処理します（後述）。

## 使っているエンコーダー

画像の書き出しには、ブラウザの標準機能（Canvas の `toBlob` など）ではなく、WebAssembly（WASM）にしたエンコーダーを使っています。ブラウザの標準機能はブラウザごとに実装が違い、細かい設定もできないためです。WASM のエンコーダーなら、どのブラウザでも同じ結果になります。

| 形式 | 使っているもの | 主な設定 |
| --- | --- | --- |
| JPEG | MozJPEG（jSquash） | プログレッシブ（既定でオン）、ハフマン符号の最適化 |
| WebP | libwebp（jSquash） | 品質 0〜100、または可逆圧縮 |
| PNG | OxiPNG（jSquash）＋ libimagequant | 減色してから OxiPNG で詰める |
| GIF | gifsicle（WASM 版） | 最適化レベル 2、非可逆度 30（既定） |
| SVG | SVGO | 安全・標準・強めの 3 段階 |
| リサイズ | jSquash の resize | Lanczos3、透過は乗算済みアルファで計算 |

MozJPEG は、従来の JPEG と互換性を保ったまま、同じ画質でファイルを小さくすることを目指して作られたエンコーダーです。PNG の OxiPNG は、画質を一切変えずに PNG の圧縮のしかたを工夫して小さくする可逆の最適化ツールです。

これらのエンコーダーは合わせると大きいため、ページを開いた時点では読み込みません。画像を入れて、その形式の処理が初めて必要になったときに読み込みます。

## 「品質」の意味は形式ごとに違う

設定の「品質」スライダー（既定は 80。プリセットの「高画質」は 90、「標準」は 80、「軽量」は 60）は、形式によって意味が変わります。

### JPEG と WebP

品質の値を、そのまま MozJPEG と libwebp の品質（0〜100）として渡します。値が小さいほど、色や細部の情報を多く間引いて小さくします。WebP で「WebP を可逆圧縮」をオンにすると品質は使わず、ピクセルを変えない可逆圧縮で書き出します。

### PNG：品質を「色数」に置き換える

PNG はもともと可逆の形式なので、品質という考え方がありません。そこで Image Adjust では、品質の値を**色数**に置き換えて減色（非可逆）してから、OxiPNG で詰めています。対応は次のとおりで、品質を 10 上げるごとに色数がおよそ 1.6 倍になるように決めています。

| 品質 | 色数 |
| --- | --- |
| 100 | 減色しない（可逆） |
| 95 | 201 色 |
| 90 | 158 色 |
| 80（既定） | 97 色 |
| 70 | 60 色 |
| 60 | 37 色 |
| 40 | 14 色 |
| 20 | 5 色 |

減色には libimagequant（pngquant の中核のライブラリ）を使い、ディザリング（色の境目を細かい点で混ぜて段差を目立たなくする処理）をかけています。libimagequant を読み込めない環境では、JavaScript だけで動く image-q で代わりに減色します。

既定の設定は「品質 80 ＝ 97 色」なので、写真のように色数の多い PNG は色が変わります。ロゴやスクリーンショットのように色数が少ない画像は、97 色でもほとんど見分けがつかないことが多い一方、グラデーションでは段差が出ることがあります。PNG の見た目を一切変えたくないときは、「PNG を減色しない（可逆）」をオンにしてください（減色せず、OxiPNG の可逆の最適化だけを行います）。

## 目標サイズの探し方

「200KB 以下」のように目標のファイルサイズを指定すると、品質を 5〜100 の範囲で二分探索します。

1. まず真ん中の品質で書き出し、目標以下ならもっと高い品質を、超えたらもっと低い品質を試します。
2. これを繰り返し、**目標以下に収まった中で最も高い品質**を採用します。書き出しは 1 枚につき 8 回までです。
3. 品質 5 でも目標に届かないときは、品質 5 の結果を出し、「目標サイズに届かなかった」と表示します。

二分探索なので、何十回も書き出し直すことはなく、96 段階の品質から 7 回ほどで答えにたどり着きます。PNG の場合は、上の表の色数を変えながら探します。WebP の目標サイズの探索は非可逆で行います。

目標に届かないのは、画像の縦横が大きすぎることがほとんどです。品質を極端に下げるより、リサイズで幅を小さくするほうが、同じサイズでもずっときれいに仕上がります。プリセットの「LP のヒーロー画像」は、幅 1920px にリサイズしたうえで 300KB 以下の WebP を探す設定です。

## 元より大きくなるときは元のまま

すでによく圧縮された画像を同じ形式で再圧縮すると、かえってファイルが大きくなることがあります。そこで、**同じ形式・同じ大きさのまま**書き出した結果が元のファイル以上になったときは、書き出した結果を捨てて元の画像を出力し、「元のままにしました」と表示します（メタデータの削除だけは行います）。GIF と SVG も同じで、最適化しても小さくならなければ元のままにします。

形式を変えたときやリサイズしたときは、大きくなってもそのまま出力します。指定どおりの形式・大きさが必要なはずだからです。

## メタデータ・向き・色の扱い

### EXIF の向きはピクセルに反映する

スマートフォンで撮った JPEG の多くは、画像そのものは横向きのまま保存し、EXIF の「向き（Orientation）」の情報で縦向きに表示させています。再エンコードすると EXIF は失われるので、そのままだと横に倒れた画像になってしまいます。Image Adjust では、JPEG をデコードするときに向きの情報どおりにピクセルを回転させてから処理するので、出力した画像は EXIF が無くても正しい向きで表示されます。

### EXIF・位置情報は残らない

PNG・JPEG・WebP を書き出し直すと、撮影日時・カメラの機種・位置情報（GPS）などの EXIF、XMP、IPTC は出力に残りません。「EXIF 等のメタデータを削除」は既定でオンです。オフにしても、再エンコードする画像からはメタデータを引き継げないため、その旨を画面でお知らせします。

一方、再エンコードしない経路（元のままにした画像・アニメーション WebP）では、元のファイルのバイト列からメタデータの部分だけを取り除きます。GIF と SVG は、最適化の中でコメントなどの付加情報を取り除きます。

### 色プロファイル（ICC）は埋め込み直す

色プロファイルは、写真の色を正しく表示するための情報です。Adobe RGB や Display P3 で撮った写真から取り除くと、色がくすんだり鮮やかすぎたりして見えます。そこで ICC プロファイルだけは、元の画像から取り出し、出力の形式に合わせて埋め込み直しています。メタデータの削除をオンにしても、色プロファイルは残ります。

## 透過とアニメーション

- **透過 → JPEG**：JPEG は透過を扱えないので、透明・半透明の部分を背景色（既定は白。設定で変えられます）と重ね合わせてから書き出します。半透明のふちも背景色となじむように計算します。
- **透過 → PNG・WebP**：透過はそのまま保ちます。WebP の可逆圧縮は、完全に透明なピクセルの下に隠れた色までは保存しない設定にしています（見た目は変わりません）。
- **アニメーション GIF**：gifsicle で、フレームを保ったまま最適化します。既定は非可逆度 30（色をわずかに崩して圧縮しやすくする）です。GIF は出力形式を選んでも GIF のまま出力します。
- **アニメーション WebP**：いまのところ変換・圧縮の対象外で、元のまま（メタデータだけ除去）出力します。
- **SVG**：SVG のまま最適化します。PNG などに変換したいときは、[アイコン生成](/icons/)を使ってください。

## SVG の 3 段階

SVG は、見た目を変えずに不要な記述を削って小さくします。SVGO の設定を 3 段階から選べます。

- **安全**：図形をパスに置き換える・パスをまとめる・数値を丸めるといった、見た目に影響しうる書き換えを止め、主にエディターが書き込む情報・コメント・メタデータを取り除きます。
- **標準（既定）**：SVGO の標準の最適化を、何度か繰り返してかけます。`viewBox` は残します。
- **強め**：座標などの数値を小数点以下 2 桁に丸めます。細かい図形がわずかにずれることがあるので、結果を確かめてから使ってください。

いずれも、表示に必要な `width`・`height` は残します。最適化した SVG のプレビューは画像として表示するので、SVG の中にスクリプトが含まれていても実行されません。

## リサイズの細かい決まり

- 幅だけ・高さだけを指定すると、もう片方は縦横比から計算します。両方を指定して「縦横比を保つ」がオンなら、指定した枠からはみ出さない大きさに収めます。
- 「元より大きくしない」（既定でオン）なら、元より大きな値を指定しても元の大きさのままにします。
- 縮小には Lanczos3 を使います。単純な間引きより輪郭がくっきり残る方式です。
- 「レスポンシブ書き出しの幅」で 640・1280・1920px を選ぶと、元の幅より小さいものだけを書き出します。元の幅が選んだ値より狭いときは、元の幅の版も 1 枚出し、`srcset` と `picture` 要素の HTML を、実際に書き出したファイル名と大きさで作ります。

## 画像はどこで処理されるか

画像の処理は、すべてお使いのブラウザの中で行います。ページの操作が固まらないよう、画像は Web Worker（画面とは別の裏側の処理）で 1 枚ずつ並列に処理します。Worker の数は端末の CPU のコア数から決め、画面の操作用に 1 コアを残します。パソコンでは最大 4、スマートフォンでは最大 2 です。GIF だけは、gifsicle が自分で Worker を立てて処理します。

### 扱える大きさの上限

上限はファイルの大きさよりも、展開したときのメモリで決まるので、主にピクセル数（幅 × 高さ）で制限しています。

| 項目 | パソコン | スマートフォン・タブレット |
| --- | --- | --- |
| 1 枚のピクセル数 | 1 億（100 MP） | 4,000 万（40 MP） |
| 1 ファイルの大きさ | 200 MB | 50 MB |
| 読み込む ZIP の大きさ | 2 GB | 500 MB |
| ZIP の中のファイル数 | 5,000 件 | 1,000 件 |
| URL から読み込む画像 | 25 MB | 25 MB |

上限を超えた画像があっても全体は止めず、その画像だけ処理せずにお知らせします。まとめて保存する ZIP が大きくなりすぎるときは、自動で複数の ZIP に分けます。

### URL から読み込むときだけ中継サーバーを使う

画像の URL を指定して読み込む機能だけは、ブラウザから他のサイトの画像を直接取得できないこと（CORS の制限）が多いため、このサイトの中継サーバーが代わりに画像を取得します。中継サーバーは画像も URL も保存せず、受け取った画像をそのままブラウザに流します。悪用を防ぐため、次の制限を設けています。

- このサイトのページからの呼び出しだけを受け付け、1 分あたりの回数を制限しています。
- 取得先は http・https の通常のポートだけで、IP アドレスの直接指定や localhost のようなローカル向けの名前、このサイト自身のドメインは拒否します。リダイレクトは 3 回まで、毎回同じ検査をしてから追います。
- 応答の種類が画像で、かつ先頭のバイト列が PNG・JPEG・GIF・WebP・SVG のものだけを返します。25 MB を超えるもの、10 秒以内に取得できないものは打ち切ります。
- 取得先のサーバーには固定の名前で問い合わせ、お使いのブラウザの情報は送りません。

ファイルを選んで読み込んだ画像は、この中継サーバーを含め、どこにも送信しません。詳しくは[プライバシーポリシー](/privacy/)をご覧ください。

## まとめ

- エンコーダーは MozJPEG・libwebp・OxiPNG・libimagequant・gifsicle・SVGO を WASM で動かし、どのブラウザでも同じ結果になるようにしています。
- PNG の「品質」は色数に置き換えています。既定の 80 は 97 色なので、見た目を変えたくないときは「PNG を減色しない（可逆）」をオンにします。
- 目標サイズは品質の二分探索で、収まる中で最も高い品質を選びます。届かないときはリサイズが効果的です。
- EXIF の向きはピクセルに反映し、EXIF・位置情報は残さず、色プロファイルは残します。
- 同じ形式・同じ大きさで大きくなるなら、元の画像を出力します。

実際の効果は画像によって大きく変わります。[変換・圧縮ツール](/)の「比較」で処理前と処理後を並べて確かめながら、設定を決めてください。

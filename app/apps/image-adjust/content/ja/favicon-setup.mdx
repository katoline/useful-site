ファビコンは、ブラウザのタブやブックマーク、履歴、検索結果などに表示される小さなアイコンです。サイトの顔として地味に効く要素ですが、いざ設置しようとすると「favicon.ico だけで足りるのか」「apple-touch-icon とは何か」「manifest は必要か」と迷いがちです。この記事では、現在のブラウザやスマートフォンで困らない最小限のファイル一式と、`head` への書き方、うまく反映されないときの確認方法をまとめます。

## 用意するファイル一式

最近の定番構成は次のとおりです。すべてを用意する必要はなく、サイトの用途に応じて取捨選択できます。

| ファイル | サイズ | 用途 |
| --- | --- | --- |
| favicon.ico | 16・32・48px を 1 ファイルに同梱 | 古いブラウザ、ルート直下の自動取得、検索エンジン |
| favicon.svg | ベクター（任意サイズ） | 最近のブラウザのタブ。ダークモード対応も可能 |
| apple-touch-icon.png | 180×180px | iOS のホーム画面追加、Safari のお気に入り |
| icon-192.png | 192×192px | Android のホーム画面、PWA |
| icon-512.png | 512×512px | PWA のスプラッシュ画面、インストール時 |
| icon-maskable-512.png | 512×512px（セーフゾーンあり） | Android で丸や角丸に切り抜かれる表示 |
| site.webmanifest | JSON | アイコンやアプリ名などの宣言 |

favicon.ico は、1 つのファイルに複数サイズの画像を入れられる形式です。16px（タブ）、32px（高解像度のタブやタスクバー）、48px（デスクトップのショートカットなど）を同梱しておけば、ほとんどの場面で足ります。

## head に貼る HTML

以下が基本のスニペットです。

```html
<link rel="icon" href="/favicon.ico" sizes="32x32">
<link rel="icon" href="/favicon.svg" type="image/svg+xml">
<link rel="apple-touch-icon" href="/apple-touch-icon.png">
<link rel="manifest" href="/site.webmanifest">
```

各行の意味は次のとおりです。

- 1 行目：ICO を従来のブラウザ向けに指定します。`sizes="32x32"` を付けているのは、ブラウザが SVG と ICO のどちらを選ぶか迷ったときに、SVG を優先してもらうための定番の書き方です。
- 2 行目：SVG のファビコンです。対応ブラウザでは、拡大縮小しても綺麗で、軽く、ダークモードにも対応できます。
- 3 行目：iOS のホーム画面用アイコンです。180×180px の PNG を 1 枚置いておけば、他のサイズは不要です。角丸は OS が自動で付けるので、画像側では角を丸めず、四角い全面塗りで作ります。
- 4 行目：Web アプリマニフェストの場所です。Android でのホーム画面追加や PWA で使われます。

`href` はルートからの絶対パス（先頭に `/`）で書くと、サブディレクトリのページでも迷いません。

## webmanifest の例

`site.webmanifest` は JSON 形式のファイルです。Android などで「ホーム画面に追加」したときの名前やアイコンを宣言します。

```json
{
  "name": "My Site",
  "short_name": "MySite",
  "icons": [
    { "src": "/icon-192.png", "sizes": "192x192", "type": "image/png" },
    { "src": "/icon-512.png", "sizes": "512x512", "type": "image/png" },
    {
      "src": "/icon-maskable-512.png",
      "sizes": "512x512",
      "type": "image/png",
      "purpose": "maskable"
    }
  ],
  "theme_color": "#ffffff",
  "background_color": "#ffffff",
  "display": "standalone"
}
```

`purpose` に `maskable` を指定したアイコンは、端末側が丸や角丸などの形に切り抜いて表示します。通常のアイコンと兼用にはせず、別のエントリにしておくと安全です。

## maskable アイコンのセーフゾーン

マスク可能なアイコンは、端末によって切り抜かれる形が違います。重要な部分は、画像の中央にある直径 80% の円（セーフゾーン）の内側に収めてください。たとえば 512px の画像なら、中心から半径 205px ほどの円の内側です。ロゴの端が円の外に出ていると、切り抜かれて欠けて見えます。

背景は、余白まで含めて全面を塗りつぶします。透過のままにすると、端末によっては背景が黒や白になり、意図しない見た目になります。

## 置き場所：ルート直下が基本

ブラウザは、`head` に指定がなくても、サイトのルート直下の `/favicon.ico` を自動で取りに行きます。そのため favicon.ico は `https://example.com/favicon.ico` で表示できる場所、つまり公開ディレクトリの直下に置くのが基本です。

他のファイルも、同じくルート直下に置いておくと、パスの管理が楽です。フレームワークによって呼び名は違いますが、静的ファイルの置き場所（`public` ディレクトリなど）に入れれば、ルート直下で配信されます。

サブパス（`/image-adjust/` のようなパス）の下でサイトを配信している場合も、ルート直下の `/favicon.ico` は、そのサイトを配信しているドメイン全体の話になります。サブパスだけにアイコンを設定したいときは、`head` で明示的にパスを指定してください。

## SVG ファビコンでダークモードに対応する

SVG ファビコンの中には CSS を書けるので、`prefers-color-scheme` でダークモードに対応できます。ブラウザのタブが暗い色のとき、黒いロゴが見えなくなる問題の解消に便利です。

```svg
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 32 32">
  <style>
    .mark { fill: #1a1a1a; }
    @media (prefers-color-scheme: dark) {
      .mark { fill: #f5f5f5; }
    }
  </style>
  <circle class="mark" cx="16" cy="16" r="12" />
</svg>
```

注意点が 2 つあります。まず、SVG ファビコン内の `prefers-color-scheme` への対応状況や挙動はブラウザによって異なるため、使うブラウザで実際に確認してください。次に、ICO や PNG は色が固定なので、この対応は SVG 限定です。そのため、どちらの背景でも見える配色にしておくのも有効な手です。

## 変更しても反映されないときの対処

ファビコンは強くキャッシュされます。差し替えたのに古いまま表示される場合は、次を順に試してください。

1. ファビコンの URL に直接アクセスして、新しい画像が配信されているか確認する。
2. ブラウザのキャッシュを消すか、スーパーリロード（Ctrl+Shift+R、Mac は Cmd+Shift+R）を試す。
3. シークレットウィンドウで開き直す。
4. ファイル名を変える、または `href="/favicon.ico?v=2"` のようにクエリを付けて、URL を新しくする。
5. CDN やリバースプロキシを使っている場合は、そのキャッシュも消す。

ファイル名を変えると、キャッシュを確実に回避できます。ブックマークに登録されたアイコンは別に保存されているため、更新されるまでに時間がかかることがあります。

## Google 検索結果のファビコン

Google の検索結果には、サイトのファビコンが表示されます。表示のための主な条件は次のとおりです（詳細は [Google 検索セントラルのドキュメント](https://developers.google.com/search/docs/appearance/favicon-in-search) を参照してください）。

- ホームページに `<link rel="icon">` を置く（ホームページとは、ドメインやサブドメインのトップページです）。
- 正方形の画像にする。サイズは 48px の倍数（48・96・144px など）が推奨され、最小は 8×8px。SVG も使える。
- Googlebot-Image と Googlebot がファビコンのファイルとホームページの両方にアクセスできる（robots.txt でブロックしない）。
- サイトの内容にふさわしい、不適切でないアイコンにする。

なお、検索結果の表示は Google が決めるため、設定してもすぐ反映されるとは限りません。反映に日数から数週間かかることがあります。Search Console でホームページの再クロールをリクエストすると、早まる場合があります。

## よくある失敗と確認方法

- 画像が正方形でなく、変に引き伸ばされたり、余白が付いたりする。元画像を正方形にしてから書き出す。
- ICO を単なるリネームで作った（PNG の拡張子だけを変えた）。ブラウザによっては表示できる場合もあるが、複数サイズ同梱の正式な ICO を作るほうが確実。
- `href` のパスが相対パスで、下層ページでは 404 になる。先頭を `/` にした絶対パスにする。
- 開発環境では見えているのに、本番で 404。デプロイ対象のディレクトリに入っているか確認する。
- apple-touch-icon の背景が透過で、iOS で黒く表示される。全面を塗りつぶした画像にする。
- 小さい表示で潰れて見えない。16px で見て判別できるよう、細い線や小さな文字は避け、シンプルな形にする。

確認は次の手順がおすすめです。ブラウザで各ファイルの URL を直接開き、表示されること（ステータスが 200 であること）を確認します。そのうえで、開発者ツールの「ネットワーク」タブで 404 が出ていないか、また「Application」パネルのマニフェスト項目でアイコンが読み込めているかを見ます。Lighthouse の PWA 関連の診断でも、マニフェストの問題を拾えます。

## 一式をまとめて作る

ここまでのファイルを手作業で書き出すのは手間がかかります。本サイトの [ファビコン・アイコン生成ツール](/icons/) は、元の画像から favicon.ico（16・32・48 同梱）、favicon.svg（元画像が SVG のとき）、favicon-16x16.png、favicon-32x32.png、apple-touch-icon.png（180px）、icon-192.png、icon-512.png、icon-maskable-512.png、site.webmanifest、og-image.png（1200×630）を ZIP でまとめて生成します。`head` 用の HTML スニペットもコピーできます。画像はブラウザ内で処理され、サーバーには送信されません。

元画像は、できれば 512px 以上の正方形で、SVG か大きな PNG を用意するのがおすすめです。画像形式の違いについては、[画像形式の選び方](/guide/image-formats/) も参考にしてください。

## まとめ

- ファイル一式は、favicon.ico、favicon.svg、apple-touch-icon.png、icon-192.png、icon-512.png、maskable アイコン、site.webmanifest が基本。
- ルート直下に置き、`head` に `link` を書く。
- SVG なら `prefers-color-scheme` でダークモードに対応できる。
- 反映されないときはキャッシュを疑い、URL を変えて確認する。
- Google 検索では、ホームページに `link rel="icon"` を置き、48px の倍数の正方形にする。

初めて設置するときは、まず [生成ツール](/icons/) で一式を作り、ルート直下に置いて確認するのが最短です。

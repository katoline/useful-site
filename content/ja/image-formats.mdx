Web サイトやブログに画像を載せるとき、最初に迷うのが「どの形式で保存するか」です。形式を間違えると、写真なのにファイルが重すぎたり、ロゴの輪郭がにじんだり、透過したいのに背景が白く残ったりします。この記事では、JPEG・PNG・WebP・SVG・GIF の特徴を整理し、AVIF にも軽く触れたうえで、用途別の選び方をまとめます。

先に結論を書くと、写真は JPEG か WebP、ロゴやイラストや文字の多いスクリーンショットは PNG か WebP、拡大縮小しても綺麗に見せたいロゴやアイコンは SVG、アニメーションは（可能なら動画や WebP を検討しつつ）GIF、という使い分けが基本です。

## まず押さえる 3 つの軸

画像形式の違いは、ほとんど次の 3 つの軸で説明できます。

### 非可逆圧縮と可逆圧縮

非可逆圧縮は、人間の目に気づかれにくい情報を捨ててファイルを小さくする方式です。JPEG や、WebP の非可逆モードがこれにあたります。品質を下げるほど小さくなりますが、保存を繰り返すと劣化が積み重なります。

可逆圧縮は、元の画素情報を一切捨てずに、zip のようにデータを詰める方式です。PNG や GIF、WebP の可逆モードがこれにあたります。画質は変わりませんが、写真のように色が細かく変化する画像では、ファイルが大きくなりがちです。

### ラスター画像とベクター画像

JPEG・PNG・WebP・GIF は、画素（ピクセル）の集まりで表現するラスター画像です。拡大すると粗くなります。一方 SVG は、線や図形を数式と座標で記述するベクター画像で、どれだけ拡大しても輪郭が滑らかなままです。ただし、写真のような複雑な階調の表現には向きません。

### 透過とアニメーション

背景を透明にできるか（アルファチャンネル）、アニメーションを持てるかも形式ごとに違います。JPEG は透過もアニメーションも扱えません。PNG は透過に対応し、GIF と WebP はアニメーションにも対応します。

## 形式ごとの特徴

### JPEG

写真向けの定番形式で、非可逆圧縮です。滑らかな階調の写真を小さくするのが得意で、品質を 70〜85 程度にすると、見た目をあまり損なわずにファイルを大きく減らせることが多いです（目安）。

弱点は、文字や細い線、ベタ塗りの境界に「モスキートノイズ」と呼ばれるにじみが出やすいことです。また透過に対応していないため、背景を抜いた画像には使えません。

### PNG

可逆圧縮で、透過（半透明を含む）に対応します。ロゴ、イラスト、図解、文字を含むスクリーンショットなど、輪郭をくっきり保ちたい画像に向いています。色数の多い写真を PNG にするとファイルがとても大きくなるので、写真には基本的に向きません。

なお PNG には、256 色以下に減色して容量を減らす PNG-8 のような使い方もあります。色数の少ないロゴやUI部品なら、見た目をほぼ保ったまま大幅に軽くできる場合があります。

### WebP

Google が開発した形式で、非可逆と可逆の両方、透過、アニメーションをひとつの形式で扱えます。同程度の見た目で比べると、JPEG や PNG より小さくなることが多いとされています（画像によって差があり、一律に何割小さくなるとは言えません）。

ブラウザ対応は、現行の主要ブラウザ（Chrome・Firefox・Edge・Safari）ですべて対応しています。Safari は 14 以降です。かなり古い環境を考慮する場合を除き、Web 用途では実用上問題なく使えます。対応状況は [MDN のブラウザ互換性表](https://developer.mozilla.org/ja/docs/Web/Media/Guides/Formats/Image_types) で確認できます。

### SVG

XML ベースのベクター形式で、ロゴ、アイコン、シンプルなイラストに最適です。拡大縮小しても劣化せず、高解像度ディスプレイでも綺麗に表示されます。ファイルも小さく済むことが多く、CSS で色を変えたり、`prefers-color-scheme` に応じて配色を切り替えたりもできます。

注意点として、写真のような複雑な画像を SVG に変換しても、軽くも綺麗にもなりません。また、外部から受け取った SVG にはスクリプトが含まれうるので、信頼できないファイルを `img` 以外の方法で埋め込むのは避けてください。

### GIF

256 色までのパレットを使う可逆圧縮の形式で、簡易的なアニメーションが扱えます。透過は 1 ビット（完全に透明か不透明か）で、半透明は表現できません。色数が少ないため写真には向かず、アニメーションの GIF はファイルが大きくなりがちです。

長めのアニメーションや写真のような動画風の素材は、MP4 や WebM の動画、あるいは WebP アニメーションにしたほうが、はるかに軽くなる場合があります。

### AVIF（参考）

AVIF は新しい世代の形式で、非可逆・可逆、透過、アニメーションに対応し、同じ見た目なら JPEG や WebP より小さくなる傾向があります。対応ブラウザも増えていますが、エンコードに時間がかかる、対応していないツールがまだある、といった事情があります。なお、本サイトの [画像変換・圧縮ツール](/) は AVIF 出力に対応していません。AVIF を使う場合は、別のツールで作成してください。

## 用途別のおすすめ早見表

| 用途 | おすすめ | 理由 |
| --- | --- | --- |
| 写真（風景・人物・商品） | WebP（非可逆）または JPEG | 階調が滑らかで、非可逆圧縮と相性が良い |
| 透過が必要な写真の切り抜き | WebP または PNG | JPEG は透過不可。WebP のほうが軽くなりやすい |
| ロゴ・アイコン | SVG（なければ PNG・WebP） | 拡大しても劣化せず軽い |
| 図解・イラスト | PNG・WebP（可逆）または SVG | 輪郭がにじまない |
| 文字の多いスクリーンショット | PNG または WebP（可逆） | JPEG だと文字の周りにノイズが出る |
| 簡易アニメーション | WebP アニメーション・動画・GIF | 長いものは動画のほうが軽い |
| OGP 画像（SNS 共有用） | PNG または JPEG | 一部の SNS が WebP に対応していない場合がある |
| メール添付・古いシステムへの提出 | JPEG または PNG | 互換性が最優先 |

## 写真・イラスト・スクリーンショットでの考え方

### 写真

色が連続的に変わる写真は、非可逆圧縮が効きます。JPEG か WebP で、品質 75〜85 前後から試し、見た目が許容できる範囲で下げていくのが定石です。大きすぎる画像はまず縮小してから圧縮すると、効果が大きくなります。変換は [JPEG から WebP](/convert/jpeg-to-webp/) や [PNG から JPEG](/convert/png-to-jpeg/) のツールで手早くできます。

### イラスト・ロゴ

ベタ塗りと輪郭が中心の画像は、可逆の PNG・WebP、またはベクターの SVG が向いています。JPEG にすると、輪郭の周りにノイズが出て、むしろファイルも大きくなることがあります。

### スクリーンショット

文字や UI 部品が多いスクリーンショットは、PNG か可逆 WebP が基本です。ただし、ブラウザ画面全体のように面積が大きくて内容が写真に近い場合は、非可逆 WebP や JPEG のほうが十分小さくなることもあります。迷ったら両方で書き出して、見た目とサイズを比べるのが確実です。

## ブラウザ対応と安全な出し分け

JPEG・PNG・GIF・SVG は、ほぼすべての環境で表示できます。WebP も現行の主要ブラウザすべてが対応しており、Safari は 14 以降です。それでも古い環境に配慮したい場合は、`picture` 要素で形式を出し分けられます。

```html
<picture>
  <source srcset="photo.webp" type="image/webp">
  <img src="photo.jpg" alt="商品の写真" width="1200" height="800">
</picture>
```

ブラウザは上から順に見て、対応している形式の `source` を採用します。どれにも当てはまらなければ `img` の `src` が使われます。この仕組みの詳しい使い方は、[LP の画像を軽くするコツ](/guide/optimize-lp-images/) でも解説しています。

## メタデータ（EXIF など）にも注意

デジタルカメラやスマートフォンで撮影した JPEG には、EXIF というメタデータが含まれます。撮影日時、カメラの機種、向き、場合によっては GPS による撮影場所などです。そのまま Web に公開すると、意図せず位置情報などが漏れることがあります。

PNG や WebP にも、形式ごとにテキストや ICC プロファイルなどのメタデータを持たせられます。公開用の画像では、不要なメタデータは削除するのが基本です。ファイルサイズも少し減ります。

ただし、画像の向き情報（EXIF の Orientation）を削除すると、縦横が正しく表示されなくなる場合があります。変換前に向きを正しく反映した状態にしておくと安全です。

本サイトの [画像変換・圧縮ツール](/) は、画像をブラウザ内で処理し、サーバーには送信しません。EXIF などのメタデータは既定で削除されるので、公開用に整えるのに使えます。

## 迷ったときの判断フロー

1. 拡大縮小しても綺麗でなければならないロゴやアイコンか。はいなら SVG。
2. 写真か。はいなら WebP か JPEG（非可逆）。
3. 透過が必要か。はいなら PNG か WebP。
4. 文字や細い線が主役か。はいなら PNG か可逆 WebP。
5. アニメーションか。はいなら動画か WebP アニメーション、簡易なら GIF。

最終的には、実際に書き出してサイズと見た目を比べるのが一番確実です。形式を決めたら、[圧縮ツール](/compress/webp/) で容量を詰めましょう。JPEG は [JPEG の圧縮](/compress/jpeg/)、PNG は [PNG の圧縮](/compress/png/)、SVG は [SVG の圧縮](/compress/svg/) からも行えます。

## まとめ

- 写真は JPEG か WebP、ロゴやイラストは SVG・PNG・WebP、アニメーションは動画か WebP を優先して検討する。
- WebP は現行の主要ブラウザすべてで対応（Safari は 14 以降）。Web 用途では積極的に使える。
- 透過が要るなら JPEG は選べない。
- 公開前に EXIF などの不要なメタデータを削除する。
- ファビコンのように特殊な形式一式が必要な場合は、[ファビコンの設置方法](/guide/favicon-setup/) を参照する。

形式の選び方は「画像の中身」と「使う場所」で決まります。この記事の表を目安に、まずは試してみてください。
